一、HTML 超連結 (Hyperlinks)

對應教材：mvshtmlch06.ppt / htmlch06.zip

1. URL 格式與 7 種 Scheme (服務協定)

  • URL 標準格式：scheme://host[:port]/path/filename
    • scheme：連線服務協定（下表 7 種）
    • host：連接電腦的 IP 位址或領域名稱 (Domain Name)
    • port：伺服器埠號（一般 Web Server 預設為 80，可省略）
    • path：檔案路徑名稱；filename：被連結的檔案名稱
Scheme 名稱與用途說明 宣告範例
http 超本文傳輸協定 (HyperText Transfer Protocol)，供 Web 伺服器傳送 HTML 網頁至瀏覽器。 <a href="http://www.nfu.edu.tw">國立虎尾科技大學</a>
file 連結至本地 (Local) 電腦上的檔案，不可用於需經 Internet 網路的擷取。 <a href="file:///e|/chart-7/link-d.htm">日記告白</a>
ftp 檔案傳輸協定 (File Transfer Protocol)，用於 FTP 伺服器檔案上傳或下載。 <a href="ftp://ftp.tku.edu.tw/ftp/incoming/">檔案下載</a>
mailto 電子郵件服務，將信件寄給郵件伺服器上的某個帳號。 <a href="mailto:diy@mail.hpdiy.com.tw">留言</a>
telnet / news / gopher 遠端登入服務 (telnet)、網路新聞群組 (news)、選單式資訊檢索 (gopher)。 Internet 常見 7 種 scheme 之一

2. 相對路徑 vs. 絕對路徑 與 <base> 標籤

💡 為什麼課本強力推薦使用「相對路徑」？
同一網站內的網頁以相對路徑設定超連結（瀏覽器會自動組合：目前路徑 + 相對路徑），當整個網站要搬移到另一台 Server 伺服器時，直接把整個目錄 Copy 過去即可運作，不必逐一修改網址。只有在連往「非本站（外部網站）」時才用絕對路徑。
連結目標 寫法規則 課程範例
同層目錄檔案 直接寫檔名 <a href="research.html">研究方向</a>
次層 (子) 目錄檔案 次目錄名稱/檔名 <a href="ch061/link-b.html">伊蔻的日記告白</a>
上層 (父) 目錄檔案 以 ../ 代表上一層目錄 <a href="../6-2.html">回上頁</a>
指定基準相對位址 <base> 只能定義在檔頭區 <head>...</head> 內，作為 <body> 所有相對超連結的基準。 <head><base href="http://localhost:51056/htmlch05" /></head>

3. 連接到同一個檔案或另一個檔案的某一段（錨點 / 標號）

  1. 步驟一（設定標號名稱）：在目標位置使用 name 屬性：
    <a name="date-1">日期：1995.02.11</a>
  2. 步驟二（超連結呼叫標號）：在 href 的標號名稱前加上 # 符號：
    • 連到同一個檔案的某段：<a href="#date-1">日期：1995.02.11</a>
    • 連到另一個檔案的某段（檔名#標號）：<a href="6-5.html#date-1">[日期：1996.02.11]</a>

4. 超連結顏色設定與快速鍵 (AccessKey)

  • 超連結顏色（設定於 <body> 標籤內）： <body link="顏色" vlink="顏色" alink="顏色">
    • link：尚未被點選過的超連結顏色。
    • vlink：已被點選過的超連結顏色（範例 6-7 設為綠色）。
    • alink：被滑鼠按下時（按著不放、尚未放開）的顏色（範例 6-7 設為粉紅色）。
  • 快速鍵設定（設定於 <a> 標籤內）： <a href="6-5.html#date-2" accesskey="b">[日期：1996.02.25](alt+b)</a>
    • accesskey 設定值為英文字母（不分大小寫），按下 Alt + 英文字母 會聚焦到該超連結。

1. 圖檔格式、背景圖與插入圖片 <img>

  • 常見網頁圖檔格式：gif（支援動畫如 google.gif）、jpg、png。

hspace="n" / vspace="n" hspace：圖片左右兩旁（水平方向）與文字間的縫隙 (pixel)；
vspace：圖片上下兩端（垂直方向）與文字間的縫隙 (pixel)。
align="?"
（文字與圖片排列）		 • bottom（內定值/預設值）：文字的第一列與圖片下方對齊
• middle：文字的第一列與圖片中間對齊
• top：文字的第一列與圖片上方對齊
• left：圖片靠左顯示，文字從圖片右上方往下顯示

三、Well-Formed XML（良構的 XML 文件）與 Namespaces

對應教材：xmlch02.ppt ~ xmlch05.ppt

1. Well-Formed XML vs. Validating XML 與字碼集

  • 字集設定：第一列 <?xml version="1.0" encoding="utf-8"?> 中，encoding 必須與檔案實際存檔編碼一致。若省略 encoding 或省略整行宣告，則預設採用 Unicode (UTF-8 或 UTF-16)，不可用 Big5。
  • Well-Formed XML 文件：滿足 XML 基本語法規則，且沒有引用任何 DTD（使用 non-Validating parser 檢查）。
  • Validating XML 文件（使用 Validating parser 檢查），必須同時滿足 4 大條件：
    1. 該份 XML 文件本身是 Well-Formed。
    2. 該份 XML 文件有引用 DTD（或 XML Schema）。
    3. 所引用的 DTD / XML Schema 本身語法正確。
    4. XML 文件內容結構完全遵守 DTD / XML Schema 的規則。

2. XML 物件命名規則（標籤、元素、屬性、實體通用）

✅ 命名 3 大鐵律
  1. 開頭第一個字元：必須是 「文字（英文字母或中文字）」、_ 或 :（絕對不可以是數字、.、- 或其他符號）。
  2. 不可有空白格：名稱中間不能出現空格。
  3. 允許字元：只能由「文字、數字、_、-、.、:」組成。

合法範例：Name、_Name、First-Name、First.Name、_875ROM、職業

❌ 常見錯誤命名（考試陷阱）
  • 875ROM ❌（開頭不可以是數字）
  • .875ROM ❌（開頭不可以是 .）
  • First Name ❌（中間有空白格）
  • First%Name、First*Name ❌（含有非法符號 %、*）

3. Well-Formed XML 十大必考條件（改錯題檢核表）

條件項目 正確規範與常見錯誤範例
1. XML 宣告指令 若有寫必須在第一列，<?xml 中間不可有空白，xml 必小寫，且必須有 version="1.0"，結尾為 ?>。
2. 唯一根節點 (Root) XML 是一個 Tree 結構，文件本體區只能有一個根標籤涵蓋所有子標籤與資料。
3. 對稱型標籤成對 有開始 <tag> 就必須有結束 </tag>，不可省略任一，且結束斜線在前面（寫成 <discount/> 當結尾是錯的）。
4. 空標籤格式 空標籤結束前必須加上 /，如 <hr size="5"/>、<p />、<img src="gif" />。
5. 滿足巢狀排列 對稱型標籤不可互相重疊交錯！
❌ <name>陳彼德<birthday></name>02/21/1972</birthday>
6. 大小寫有別 英文字母大小寫視為不同標籤！<price>12100</Price> ❌（p 與 P 不同）。
7. 屬性值必加引號 屬性值必須用成對的 "..." 或 '...' 包起來（id=X123 ❌、currency='NT" ❌）。
8. 不可重複屬性 同一個標籤內相同屬性只能設定一次（不同標籤則可出現相同屬性名）。
9. 特殊字元實體引用 5 個特殊字元必須用代替符號：
& → &amp; ｜ < → &lt; ｜ > → &gt; ｜ " → &quot; ｜ ' → &apos;
（或者使用 <![CDATA[ ... ]]> 區塊原封不動顯示純文字；註解為 <!-- ... -->）
10. 正確物件名稱 遵守上方命名規則，且標籤括號與斜線間不可亂加空白（如 < /課程 > ❌）。

4. Namespaces（名稱空間，第五章 xmlch05.ppt）

  • 使用原因：① 引用不同的標示語言（如 XHTML 與 MathML 混用）、② 避免同名標籤/屬性的衝突。
  • 明確宣告 vs. 內定宣告：
    • 明確宣告：xmlns:aw="http://www.aecro.com.tw/ns/aw/1.2" → 使用時加前綴 <aw:person>。
    • 內定宣告：xmlns="http://www.aecro.com.tw/ns/op/1.0" → 不加 :名稱，涵蓋該標籤及其所有子標籤。
  • 必考三大規則：
    1. 覆蓋原則：明確宣告一定會覆蓋內定宣告；若同為內定或同為明確，則引用距離最近（最內層）的宣告。
    2. 屬性不適用內定宣告：內定宣告（xmlns="URI"）只作用在標籤名稱，無法作用於屬性！屬性預設是「無 Namespaces」，若屬性要用 Namespace 必須使用明確宣告（如 op:number="A1"）。
    3. 屬性 URI 衝突：同一標籤中若兩個屬性使用不同前綴（如 a:sex="男" b:sex="男"），但 a 與 b 對應的 URI 完全相同，仍視為重複屬性（Not Well-Formed XML）！

四、DTD 文件型態定義 (Document Type Definition)

對應教材：xmlch06.ppt & xmlch08.ppt (DoD / dpp)

1. DTD 宣告方式（內部 DTD vs. 外部 DTD）

<!-- 1. 內部 DTD：直接寫在 XML 檔頭區 -->
<!DOCTYPE PersonData [
    <!ELEMENT PersonData (name, birthday, occupation+, spouse?, email*)>
    <!ELEMENT name (#PCDATA)>
]>

<!-- 2. 外部私人 DTD (SYSTEM) -->
<!DOCTYPE PersonData SYSTEM "6-5.dtd">

<!-- 3. 外部公開共用 DTD (PUBLIC)，名稱格式為 "-//制定者//敘述//語言" -->
<!DOCTYPE wml PUBLIC "-//WAPFORUM//DTD WML 1.2//EN" "http://www.wapforum.org/DTD/wml12.dtd">

2. 元素設定 <!ELEMENT> 與出現次數符號

元素型態 / 符號 語法範例 重點說明
一般文字 (#PCDATA) <!ELEMENT name (#PCDATA)> 元素內容為一般可剖析文字資料。
空元素 EMPTY <!ELEMENT breakline EMPTY> 在 XML 本體中對應空標籤 <breakline />，不可包任何資料。
不限次序與次數 ANY <!ELEMENT PersonData ANY> 可包含任何已宣告元素或文字，不限次序與次數（每個 DTD 只允許一個 ANY）。
選擇型元素 (A | B) <!ELEMENT 銀行代款 (國內銀行|國外銀行)> 子元素只能二選一出現（不可同時出現，也不可都不出現）。
混合型元素 <!ELEMENT email (#PCDATA|hotmail|yahoo)*> 可同時包含文字與子元素，#PCDATA 必須寫在最前面。
出現次數符號 無符號 = 恰 1 次（內定值）
? = 0 或 1 次
* = ≥ 0 次（0、1 或多次）
+ = ≥ 1 次（至少 1 次）		 例：(name, occupation+, spouse?, email*)
→ name 必 1 次、occupation 至少 1 次、spouse 0~1 次、email 0~多次。

3. 屬性設定 <!ATTLIST>：4 種內定值 與 10 種屬性型態

基本語法：<!ATTLIST 元素名稱 屬性名稱 屬性型態(Type) 內定值型態(Default-value)>

4 種屬性內定值型態 (Default-value)
#REQUIRED 元素中必須出現該屬性（必填）。
#IMPLIED 元素中可以不用出現該屬性（選填）。
#FIXED "值" 屬性值固定不可變（省略時自動帶入；有寫則必等於該值）。
"預設字串" 有內定值（省略時自動帶入；有寫時可改為其他合法值）。
常考屬性資料型態 (共 10 種)
CDATA 一般文字與數字字串。
(值1|值2) Enumerated 列舉型態（例：(男|女) "男"）。
NMTOKEN / NMTOKENS 由文字、數字、. : _ - 組成，開頭可以是數字（如 123-YY1 合法）；NMTOKENS 以空白隔開多個值。
ID / IDREF / IDREFS ID 全文件唯一且開頭不可是數字；IDREF 必須參考文件中已存在的 ID 值。
ENTITY / ENTITIES / NOTATION 外部實體（單一/多個空白分隔）與已宣告的 Notation。

五、JavaScript XML DOM 與 dom-8.html 深度解析

對應教材：MVSJSDOMFetch.pptx / dom-1 ~ dom-8.html

1. DOM 節點類型 (nodeType) 與核心 API

Node Type 名稱 nodeType 值 重點說明與常用 API
Element（元素節點） 1 標籤節點（如 <book>）。走訪 childNodes 時必用 if (node.nodeType == 1) 過濾！
Attribute（屬性節點） 2 標籤屬性（如 sales="Y"），可用 elem.getAttribute("sales") 讀取。
Text（文字節點） 3 文字內容，包含 XML 標籤與標籤之間的「換行與縮排空白」！
Comment / Document 8 / 9 註解節點為 8；Document 文件根節點為 9。

2. 必考程式：dom-8.html 完整程式碼與注解

dom-8.html 是整個 DOM 單元的母體程式（後續作業 domhw-2 ~ domhw-5 都是由它修改而來）：

fetch('book4.xml')
    .then(response => response.text())
    .then(str => (new window.DOMParser()).parseFromString(str, "text/xml"))
    .then(xmlDom => {
        // 1. 顯示根元素名稱 (booklist) 與根元素底下所有文字內容
        document.write(xmlDom.documentElement.tagName);
        document.write("(" + xmlDom.documentElement.textContent + ")<br />");

        // 2. 取出根元素 (booklist) 的所有子節點 (含空白換行 Text 節點與 book 元素節點)
        fnodeList = xmlDom.documentElement.childNodes;

        // 3. 第一層迴圈：走訪每個 <book>
        for (let i = 0; i < fnodeList.length; i++) {
            if (fnodeList[i].nodeType == 1) { // 只處理 Element 節點 (type 1)
                document.write("&nbsp;&nbsp;+-- " + i + ":" + fnodeList[i].tagName);
                document.write("(" + fnodeList[i].textContent + ") <br />");

                // 4. 若 <book> 擁有子節點，進入第二層迴圈走訪 code, title, author, price
                if (fnodeList[i].hasChildNodes()) {
                    snodeList = fnodeList[i].childNodes;
                    for (let j = 0; j < snodeList.length; j++) {
                        if (snodeList[j].nodeType == 1) { // 只處理 Element 節點 (type 1)
                            document.write("&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;+-- " + snodeList[j].tagName);
                            document.write("(" + snodeList[j].textContent + ")<br />");
                        }
                    }
                }
            }
        }
    })
    .catch(error => console.error('Error loading XML:', error));
🔥 考前必背問答：為什麼 dom-8.html 輸出是 +-- 1:book、+-- 3:book、+-- 5:book？

因為在 book4.xml 中，<booklist> 與各個 <book> 標籤之間有換行與空白字元，DOM 剖析器會將這些換行空白視為 Text 節點 (nodeType == 3)，放在 fnodeList[0]、fnodeList[2]、fnodeList[4]、fnodeList[6]；而真正的 <book> 元素節點 (nodeType == 1) 則位於索引 1、3、5。由於程式加了 if (fnodeList[i].nodeType == 1)，因此只印出 i = 1, 3, 5。

fetch('book5.xml')
    .then(response => response.text())
    .then(str => (new window.DOMParser()).parseFromString(str, "text/xml"))
    .then(xmlDom => {
        let html = "<table border='1'><tr><th>書號</th><th>書名</th><th>作者</th><th>價錢</th><th>是否有存貨</th></tr>";
        let books = xmlDom.getElementsByTagName("book");
        for (let i = 0; i < books.length; i++) {
            let code = books[i].getElementsByTagName("code")[0].textContent;
            let title = books[i].getElementsByTagName("title")[0].textContent;
            let price = books[i].getElementsByTagName("price")[0].textContent;
            let sales = books[i].getAttribute("sales"); // 讀取 sales 屬性 (Y/N)

            // 處理多位作者
            let authorNodes = books[i].getElementsByTagName("author");
            let authorStr = "";
            for (let j = 0; j < authorNodes.length; j++) {
                authorStr += authorNodes[j].textContent + " ";
            }

            html += "<tr>";
            html += "<td>" + code + "</td>";
            html += "<td>" + title + "</td>";
            html += "<td>" + authorStr.trim() + "</td>";
            html += "<td>" + price + "</td>";
            html += "<td>" + sales + "</td>";
            html += "</tr>";
        }
        html += "</table>";
        document.write(html);
    })
    .catch(error => console.error('Error loading XML:', error));

【第 7 題｜簡報作業原題 hw5-1.xml 與 5-12.xml Namespace 觀念】

(1) 在底下 <課程> 內宣告一內定的 namespace，在 <教師> 內宣告一明確的 namespace（並修正原題結尾標籤錯誤 < /課程 >）。
(2) 在範例 5-12.xml 中，為何 <bad n1:a="1" n2:a="2" /> 不合法，但 <good a="1" n1:a="2" />（即使有設內定 xmlns="http://www.w3.org"）卻合法？

👉 點擊查看 hw5-1.xml 與 5-12.xml 標準解答

(1) hw5-1.xml 解答：

<?xml version="1.0" encoding="utf-8"?>
<課程 id="39393" xmlns="http://www.nfu.edu.tw/ns/course">
  <課名 學分="3">Web技術與應用</課名>
  <教室>綜三館501</教室>
  <t:教師 id="ART-7529" sex="男" xmlns:t="http://www.nfu.edu.tw/ns/teacher">
    <t:姓名>許乙清</t:姓名>
    <t:興趣>慢跑</t:興趣>
    <t:興趣>爬山</t:興趣>
    <t:興趣>Coffee</t:興趣>
    <t:興趣>Tea</t:興趣>
  </t:教師>
</課程>

(2) 5-12.xml 關鍵解析：因為 n1 與 n2 都是明確宣告且指向同一個 URI (http://www.w3.org)，所以 n1:a 與 n2:a 實質上是同一個屬性，違反重複屬性限制；但內定宣告 (xmlns="...") 不會作用在屬性上，因此 <good a="1" n1:a="2" /> 中的 a 屬於「無 Namespace」，而 n1:a 屬於 http://www.w3.org，兩者不同，故為合法的 Well-Formed XML！
